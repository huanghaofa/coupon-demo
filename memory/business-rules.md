# 已确认业务规则

1. 报表一行对应一个卡券实例 ID。
2. 实例报表和 E3S 提交记录只展示 VIN、手机号码、oneID，不设置“归属类型”。
3. 商城回传粒度为订单商品和卡券实例的关系明细，必须含商品是否适用本卡券、适用性原因、商城商品单价、该商品分摊的实际优惠金额、网点价以及 VIN、手机号码、oneID。
4. 卡券面值由卡券中心自行读取，商城不重复回传。
5. 结算前先过滤适用商品；不适用商品保留明细但不参与任何价格、优惠或退款汇总。
6. 卡券实例有效优惠金额 = 适用商品优惠合计 - 已退适用商品对应优惠合计。
7. 单实例有效优惠金额最低为 0，退款以扣减字段和明细表达，不新增一行负数实例。
8. 应结算金额沿用原有结算规则计算，不新增商城专属规则。
9. 线上结算价格标准值可选商城商品单价、实际优惠金额、卡券面值或网点价；除卡券面值外，均仅汇总适用商品。
10. 核销渠道与核销来源分别记录：来源为商城时渠道为线上，来源为 E3S 时渠道为线下。
11. 订单尚可退款时，只能展示预计结算金额，不可发送 E3S。
12. 商城确认订单不可再退款后，卡券中心冻结该订单关联卡券实例的最终优惠和应结算金额。
13. 每次订单冻结后，卡券中心立即通过接口提交一次 E3S 结算；不人工勾选，不生成批次。
14. E3S 提交必须使用唯一请求 ID 做幂等控制，避免同一次订单冻结重复结算。
15. 卡券规则不维护结算渠道字段；每套规则同时维护线上和线下配置。
16. 实际结算时根据卡券实例核销渠道自动路由：线上选择线上配置，线下选择线下配置。
17. 卡券规则设置页面保留查询、新增、编辑、删除和导出。
18. 已存在核销记录的结算规则禁止编辑和删除。
