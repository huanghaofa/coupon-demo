# 商城卡券结算原型需求基线

## 产品目标

为卡券中心补齐线上商城卡券结算能力。新商城按“订单商品 + 卡券实例”拆分每张卡券的优惠金额，并回传商品是否适用本卡券、商城商品单价、实际优惠金额和网点价；卡券面值由卡券中心自行读取。卡券中心只汇总适用商品并沿用原有结算规则，订单不可再退款后冻结最终金额，并自动提交一次 E3S 结算。

## 目标用户

- 卡券中心运营：查询卡券实例的优惠、退款和结算结果。
- 结算管理人员：查看订单冻结后的 E3S 接口提交和结算结果。
- 财务或审计人员：追溯单张卡券实例的金额计算过程。

## 页面范围

1. 商城卡券实例结算报表。
2. 卡券实例结算详情抽屉。
3. E3S 订单级提交记录。
4. 卡券规则设置页：沿用原有查询、新增、编辑、删除和导出功能；隐藏结算渠道字段，每套规则同时维护线上和线下配置；线上规则可从商城商品单价、实际优惠金额、卡券面值、网点价中选择结算价格标准值，并清楚标记数据来源。

## 核心交互

- 按实例 ID、卡券名称、VIN、手机号、oneID、核销渠道、核销来源和结算状态筛选。
- 点击“详情”查看订单商品是否适用本卡券、适用/不适用原因、商品级优惠拆分、退款明细和计算过程。
- 补贴金额只使用标记为“适用”的商品进行汇总；不适用商品保留明细但不进入结算基数。
- 报表分别展示核销渠道与核销来源：商城来源记为线上核销，E3S 来源记为线下核销。
- 报表展示四项价格快照及其来源，并单独展示规则选中的价格标准值、结算基数和应结算金额。
- 商城确认订单不可退款后，卡券中心冻结该订单关联实例的最终金额。
- 每次订单冻结后，系统自动通过接口提交一次 E3S 结算，不生成批次。
- 实际计算时读取卡券实例的核销渠道：线上核销使用规则中的线上配置，线下核销使用规则中的线下配置。
- 报表和 E3S 提交记录只保留 VIN、手机号码、oneID 三列，不展示或使用“归属类型”概念。

## 不在本次范围

- 不引入账期管理。
- 不设计商城端订单拆分界面。
- 不实现真实 E3S 接口和数据库写入。
- 不生成 E3S 结算批次，不设置人工勾选和批量提交。
- 不新增商城专属规则类型或渠道重复规则；原页面的新建结算规则能力仍保留。
- 不将单实例退款记录做成负数结算行。
