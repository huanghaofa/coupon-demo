# 项目决策记录

## D-001 静态原型架构

使用 HTML、CSS 和原生 JavaScript，不引入构建工具。

## D-002 结算口径

- 统计粒度为单张卡券实例，不使用账期作为报表主粒度。
- 商城按订单商品与卡券实例维度回传商品适用标记、商城商品单价、实际优惠金额和网点价；卡券面值由卡券中心自行读取，不要求商城重复回传。
- 同一订单中的不适用商品不进入结算计算，但必须保留在商品明细中并标注不适用原因，方便核对。
- 退款后按退款商品重新计算有效优惠和预计结算金额。
- 订单不可退款后冻结关联实例最终金额，随后立即通过接口提交一次 E3S 结算。
- 不生成 E3S 结算批次，不设置人工勾选、汇总或确认环节。
- 报表数据库由新商城提供，卡券中心通过接口写入。
- 同一张券可同时支持线上与线下，仍保留一套结算规则；规则维护时不配置结算渠道，线上和线下计算配置始终同时存在。
- 实际结算时以卡券实例的核销渠道作为运行时路由条件：线上核销选择线上配置，线下核销选择线下配置。
- 不新增独立商城规则类型，不按渠道生成重复规则记录；沿用现有卡券规则设置页面及其增删改查能力。
- 商城券按“线上”规则处理，复用原有“线上结算价格标准值”字段，可从商城商品单价、实际优惠金额、卡券面值和网点价中选择；字段旁标记商城传入或卡券中心读取。
- “核销渠道”与“核销来源”分开存储和展示：商城来源映射为线上核销，E3S 来源映射为线下核销；最终统一提交 E3S 不改变历史核销来源。
- 已存在核销记录的结算规则禁止编辑和删除。
- 实例报表和 E3S 提交记录分别保留 VIN、手机号码、oneID 三列，不设置“归属类型”字段或筛选项。
- E3S 提交记录保留实际存在的 VIN、手机号码和 oneID，用于结算追溯和对账。

## D-003 页面表达

- 主表展示适用商品商城价合计、适用商品实际优惠、卡券面值、适用商品网点价合计、规则选择的价格标准、结算基数和应结算金额；退款作为适用商品优惠的扣减说明，不生成负数实例行。
- 状态分为退款窗口内、E3S 处理中、已结算和无需结算。金额冻结后立即提交 E3S，不停留在人工待提交状态。
- 实例详情以商品拆分明细和计算链路作为主要追溯证据。
